# ADR-0014: 계좌 승인 상태 머신, 1인 다계좌 및 송금 거래 원장 설계

- 상태: Accepted
- 영향 범위: `module-domain`, `module-infra`, `module-api`

## 1. 배경

초기 계좌 도메인은 사용자당 단일 계좌만 허용했고, 개설 즉시 입출금이 가능했다. 실제 뱅킹 서비스에 가깝게 동작하려면 한 사용자가 목적별로 여러 계좌를 개설해 대표 계좌를 전환할 수 있어야 하고, 관리자 심사를 통과한 계좌만 거래를 허용해야 한다.

또한 계좌 간 실시간 송금이 추가되면서 단순 잔액 증감만으로는 자금 흐름을 추적할 수 없게 되었다. 입금과 출금 시점의 거래 후 잔액을 남기는 원장 테이블이 필요했다.

## 2. 결정 사항

### 2.1. 계좌 상태 머신 도입
- `AccountStatus` 열거형을 `PENDING`, `ACTIVE`, `REJECTED`, `SUSPENDED` 네 가지 상태로 정의한다.
- 신규 개설 계좌는 `PENDING` 상태로 생성되며, 관리자가 승인(`ACTIVE`)하기 전에는 결제 출금이나 송금 등 자금 이동을 도메인 메서드 내부에서 차단한다.

### 2.2. 1인 다계좌 및 대표 계좌 모델링
- `accounts` 테이블에서 `owner_id`의 유일 제약을 제거해 한 사용자가 여러 계좌를 보유할 수 있게 했다.
- `Account` 도메인에 `isPrimary` 속성을 추가하고, 결제 시 자동 출금할 대표 계좌를 `findPrimaryByOwnerId`로 조회한다. 대표 계좌 변경 API 호출 시 기존 대표 계좌를 해제하고 대상 계좌를 활성화하는 작업을 단일 트랜잭션에서 처리한다.

### 2.3. 실시간 송금 및 거래 원장 기록
- `AccountTransaction` 도메인 모델과 영속 엔티티를 추가해 송금 출금, 송금 입금, 결제 차감, 환불 등 모든 잔액 변동을 불변 레코드로 기록한다.
- 각 원장 레코드에는 거래 금액과 거래 직후 잔액(`balanceAfter`)을 함께 저장해 특정 시점의 계좌 잔액을 역산하고 감사할 수 있게 했다.

## 3. 결과 및 영향

- 관리자의 계좌 승인 및 거절 워크플로우와 일반 사용자의 다계좌 전환, 거래 내역 조회 기능이 도메인 불변식 안에서 일관되게 동작한다.
- 실시간 송금 시 복수 계좌의 잔액을 동시에 수정하므로, 교착 상태를 막기 위해 두 계좌에 대한 비관적 락 획득 순서를 계좌 ID 오름차순으로 정렬하는 동시성 규칙이 추가로 요구된다.
